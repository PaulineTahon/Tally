# Share, redesigned: a QR code for every Tally form

This is my clickable prototype for the Tally designer assignment. Task 1 asked me to simplify the Share tab and add a QR code. Task 2 asked for visuals announcing it.

**Live prototype:** https://paulinetahon.github.io/Tally/
**Announcement visuals:** https://paulinetahon.github.io/Tally/visuals/

## The idea

People don't really want to "share". They want enough of the right responses, fast. So instead of one Copy button surrounded by unrelated cards, I built the Share tab around the link and the places people share it, with the QR code as one more format of that same link.

I started with the quick win, then the bigger bet:

1. **A share sheet right after Publish, the first time.** The link and Copy always sit on top, with a compact preview card right under them: a small thumbnail, the title and the domain, the way your link shows up in a chat or a post. The card applies to every link and code, whatever the ref. Below it, "More ways to share" has three tabs: QR Code, Social and Embed. On the desktop Share tab page the card keeps the width of a real link preview and the tabs hug their labels. The first publish always opens on QR Code; after that the sheet remembers the tab you used last. The sheet eases to the height of each tab, so short tabs never leave an empty gap and Done glides instead of jumping. On a phone it's a bottom sheet with a Share button that opens the native share sheet, and the card and tabs stay compact so your QR code is in view without scrolling. Republishing a form that already has responses shows a short toast with a Share button instead, so the sheet doesn't get in the way.
2. **A calm sheet, actions in context.** Copy is the only black button (on a phone, Share is, and Copy is outlined next to it). The link options live where they apply: Use custom domain, under the link like in Tally today (Edit custom domain once one is saved), opens "Link ending and domain", and Customize preview, right under the preview card, opens the preview editor (title, description, image). Upload your own image and Replace and Remove appear next to its thumbnail; Remove goes back to the default image. Nothing is kept until Save. There is no pencil in the link field, so the ending never looks editable without a domain. On the desktop Share tab page, everything that opens (Use custom domain, Customize preview, a code's page, and in Rows and Tiles each way to share) opens in a centred modal with the same content, with Back in its header one level down. Each one takes over the whole sheet: the link, the card and the tabs step aside, the header shows a Back arrow and the view title, and Back takes you to the tab you came from. Back never saves and never asks: it puts things back the way they were saved. Escape still closes the whole sheet. In a detail view the save button is the one black button (Save on Pro, Upgrade to Save on Free); Copy isn't on screen there. On Free, Save reads Upgrade to Save and opens the upgrade pop-up, a copy of the plans pop-up on Tally today (Pro and Business, pay monthly or yearly, at tally.so/pricing prices). Upgrade there and you land back in the same view, with your values kept and Save ready. Use custom domain and every preview get the same quiet text action under them, like Tally's own Use custom domain: grey underlined text with the Pro badge right after it, no icon, and a 44px tap target on a phone. That's Customize preview under the link card and Customize code under the QR code. Add another code stays a row with its + icon. Looking at your preview is free. Social starts with one line, "We tag each link so you can see where responses come from.", then one row per place: WhatsApp, Instagram, Facebook, LinkedIn, X and Email. Every row says what it does: Copy link copies that place's tagged link and says Copied right in the row, Open opens the app (WhatsApp, or your mail app for Email) with the tagged link ready. Embed shows Standard, Popup and Full page, plus one line linking to Tally's guide on how embedding works. Pick one, then Copy code copies its snippet (with an alert), or Customize embed opens Tally's full Embed page with that layout already chosen, with its options on the left and a live preview of your form on the right, where the popup really opens. Close brings you back to the Embed tab. Embedding is free on Tally, so Customize embed has no Pro badge. A custom ending lives on your own domain (Pro), as an extra address: tally.so/r/KpYalV always keeps working, and every QR code points there, so printed codes never break. The view starts with just Custom domain; once you type one, Link ending opens under it, already filled in with the form's title as a slug (Community picnic RSVP gives community-picnic-rsvp), and you can change it. As you type, the view shows the full new link. Change a custom ending you had already saved and it tells you that custom links you've already shared stop working, next to the line that printed codes keep working.
3. **A plain black QR code, print-ready by default.** Black on white, in a rounded style: every module is its own round dot, never merged, and the corner eyes keep their square shape with rounded corners. A white Tally asterisk sits on a small black rounded tile in the middle, on every plan. The same style is used everywhere: on screen, in the PNG, SVG and PDF, in Insights and in every visual. No other branding. There's no colour picker: codes stay black so they're easy to scan, and the SVG is there for anyone who wants to recolour it. The one personal touch is a logo (Pro), which replaces the asterisk tile. The logo controls sit on the code's own page, under Download: Add your logo with its Pro badge, "Replaces the Tally mark on all your QR codes.", and Upload, Replace and Remove. Customize code opens that page scrolled to the logo, with focus on it. On Free you can still try it: the Pro badge on Customize code is there before you upload, the logo shows in the code right away, and while it's in, the black button is Upgrade to download (outlined in the QR Code tab, where Copy stays the black one), with Download without logo next to it. Upgrade to download opens the plans pop-up. Upgrade and you're back on the same page with your logo and a normal Download; remove the logo and the outlined Download PNG comes back. One plain line with the form's tally.so link always sits under the code, on screen and in every download. Download PNG saves at print size on a computer (Save image on a phone, which opens the system share sheet). It's the same split button everywhere, with SVG and PDF in a dropdown that opens above the sheet. In the QR Code tab it's outlined, so the link's Copy (Share on a phone) stays the only black button. On the code's own page, where Copy isn't on screen, it's the black button, right under the code. Error correction is level H, so the mark never stops it scanning. Every code opens tally.so/r/ with the form's ID and a `?ref` tag, never a custom domain or ending, so printed codes keep working whatever you change. Every alert (downloads, copies, Removed with Undo, saved changes) shows in the same place: at the bottom of the screen, above the sheet's footer when it has one, clear of the prototype bar and the phone's safe area. A download alert clears when you switch tab or view.
4. **One code, ready to go.** With one code, the QR Code tab shows "Your QR Code" itself with Download, and Customize code sits under its card. With two or more there is still exactly one Customize code, in the same place under the list: the logo is one setting for the whole form, used by every code on screen, in downloads and in Insights. Click the code to open its own page in the sheet, with Back and its title in the header, a bigger code with its link line, the same Download, the logo and the tracking line, in that order. There is nothing to tell apart yet, so there is no Rename. Using it in more than one place? Add another code for each place, for free, and the tab turns into a list where each code shows its own name; click any row to open that code. Once there are two, every code can be renamed without changing its link, so printed codes keep working. The Share tab lists every code and tracked link in one place, under Codes and Tracked Links: Your QR Code first, then each code and link you added, each with its submissions on one line ("0 submissions", "1 submission"), even at 0. Any code or link you added can leave the list with Remove from list, in its ... menu, here and in the sheet. There's no confirm: an alert says "Removed. The code still works and its responses stay tagged." with Undo, which puts the row back where it was. The link keeps working, and its numbers stay in Insights. Your QR Code can't be removed. The share sheet shows no counts on its code rows, and visits stay in Insights. Insights keeps every QR code in Sources at 0 visits too, so a new code never seems to go missing. You only ever see the names; the `?ref` tag stays in the link itself.
5. **Sources in Insights.** The Sources panel on the Insights tab lists your form's QR code and each extra code as its own row, by name, next to the referrers, with a Submissions column. This is the part I'd push for most: it turns sharing into a loop.

## What to try

- **Publish** in the editor and watch the share sheet open. Hit Copy and see it confirm in place.
- The sheet opens on **QR Code**. Download your code, open the format menu for SVG or PDF, then click the code to open its page and try Customize code. Scan it with your phone. Then hit **Customize preview** under the preview card, change the title, go Back and see the card follow.
- Click **Add another code**, add one for a place and download it. Then rename it.
- In **Social**, copy a link for Instagram or open WhatsApp: each one carries its own tag, so Insights shows where responses came from.
- Hit **Use custom domain** under the link, add a domain and an ending, and watch the new link build as you type. Pick **Custom ending** in the prototype bar to start from a saved one and try changing it.
- Compare the three layouts of the sheet with **Version: Tabs | Rows | Tiles** in the prototype bar, or link one straight away: no parameter for Tabs, `#/edit?variant=entry` for Rows (QR Code, Social and Embed as rows, each opening its own page) and `#/edit?variant=tiles` for Tiles (three tiles side by side, each opening its own page). Every version has the same top: the link, Use custom domain, a small Link preview label over the card, and Customize preview. Everything else in the sheet, from the code's page to Remove from list, works the same in all three. The bar stays usable while the sheet is open. Captures with `?capture=1`, and the changelog demo, leave the switch out.
- Switch the plan between Free and Pro in the prototype bar. On Free you can try a new link ending or a logo, but saving the ending or downloading a code with your logo asks you to upgrade.
- Switch the Publish state in the prototype bar to see republishing with and without responses.
- Follow the **Prototype Guide** card on each screen.
- Go to **Insights** and switch between the example states in the prototype bar.
- Try everything at phone width too.

The surrounding Tally UI is static on purpose. Only the share feature changes. Every number on the Insights tab is example data.

The visuals page has the changelog image, a poster, social images for LinkedIn and X, and a cover for the demo form. Every code in them really scans and is tagged with where it was seen. Editable, layered sources for the changelog, social and cover images are in `design-sources/`, ready to drop into Figma.

## Built with

Vite, React and TypeScript. `qrcode` for the codes (error correction level H, so a logo in the middle still scans), `jspdf` for vector PDFs and `html-to-image` for the PNG exports. Icons are Lucide, brand logos come from Simple Icons, and the type is Inter, to stay close to Tally's own UI.

```bash
npm install
npm run dev      # local dev server
npm run build    # static build in dist/
```

The site deploys to GitHub Pages through `.github/workflows/pages.yml`.
